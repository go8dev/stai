name: Plan and decision register
description: Where the STAI plan and the owner's numbered decisions live, and how to treat them across sessions.
---

The owner approves or changes the plan by item number (1 to 23: eight proposals, eight working
assumptions, seven points found on this runtime). The numbered list in
`docs/STAI_PHASE1_PLAN.md` is the reference for what each number means.

**Why:** The owner replies with bare numbers ("change 5 and 19"). After a context reset the
numbers mean nothing unless the register is read again. The owner was also promised that
nothing is built before approval and that work proceeds one phase at a time.

**How to apply:**
- Read `docs/STAI_PHASE1_PLAN.md` before starting or planning any phase.
- When the owner approves or changes an item, record the outcome in that file. Do not renumber.
- Thresholds and caps for AI cost control (item 2) are deliberately undecided until one real
  committee run has been measured; bring the numbers back to the owner rather than choosing them.
- After each phase, stop and report under five headings: completed, tested, pending, blocked,
  next recommended action.
- Each phase is set up as one task that the owner starts. Do not build or propose a later
  phase before the owner has answered the previous phase's report.
- The owner decides where a task is built: in an isolated copy or in the main project. Check
  the task's state before assuming either, and do not start until the task is assigned.
- A task can no longer be edited once the owner accepts it, which can happen within minutes.
  Put late corrections in `replit.md` and the plan's decision log, where the builder reads them.
- Replit's documentation (checked 17 Nov 2026) says an isolated task copy reflects the
  project's current files, uncommitted ones included, and can read the project's Secrets.
